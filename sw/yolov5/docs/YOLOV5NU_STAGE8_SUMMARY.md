# YOLOv5nu Stage 8 Summary

Stage 8 completed the software-only shared-scale and Concat-to-Conv dataflow
work for the YOLOv5nu 320x320 Gemmini path. Stage 8F is the frozen final
bit-exact baseline for this stage.

## Final scope

The frozen Stage 8F baseline uses seven feature-map residual Adds mapped to Gemmini
shared-scale resadd, nine single-consumer Concat-to-Conv fusions, and four
dual-consumer Concat-to-Conv fusions covering eight consumer Conv edges. The
`/model.9` SPPF four-input Concat uses a four-slice helper. Every split-K
partial boundary retains a fence. Final mvout performs Conv requant and the
Gemmini `SILU_LUT` activation.

The final graph has 17 split-K Conv consumer edges. All 13 feature Concat
outputs targeted by Stage 8 are inactive and are not allocated in the arena.

## Stage 8A: shared-scale model

Builder:

`scripts/yolov5nu_stage8a_shared_scale.py`

The initial candidate changed only `/model.2/m/m.0/Add`. It regenerated the
affected Q/DQ scale, downstream Conv Int32 bias and bias scale, Conv requant,
69 dynamic SiLU LUTs, graph manifest, and five-image ORT reference.

The cumulative seven-Add model is generated by:

`scripts/yolov5nu_stage8_all_shared_adds.py`

Model and manifest:

`generators/gemmini/software/gemmini-ort/models/detection/stage8_all_shared_adds/yolov5nu-stage8-all-shared-adds.onnx`

`generators/gemmini/software/gemmini-ort/models/detection/stage8_all_shared_adds/yolov5nu-stage8-all-shared-adds.graph.json`

The model remains signed symmetric per-tensor int8 with zero point 0. The
model.4 and model.6 residual chains are processed topologically so each Add's
two input scales agree without breaking the next Add's input contract.

## Stage 8B: Gemmini shared ResAdd

Builder:

`scripts/yolov5nu_stage8b_shared_resadd.py`

The selected Add uses identity mvin for both inputs and store scale:

```text
shared_scale / add_output_scale
```

The Add output was temporarily materialized before Concat to isolate and
validate the Gemmini resadd arithmetic. FPGA image025 validation showed about
10.6x speedup for the Add itself; the temporary Concat requant consumed most
of the end-to-end gain.

## Stage 8C: split-K Concat-Conv

The AOT generator supports:

- `8c-model2`: first model2 fusion;
- `8c-backbone-splitk`: model2/4/6/8 fusions;
- `8c-single-consumer-splitk`: all nine single-consumer fusions;
- `8c-dual-consumer-splitk`: all single- and dual-consumer fusions.

Implementation:

`generators/gemmini/software/gemmini-rocc-tests/imagenet/generate_yolov5nu_baremetal.py`

The two-slice helper maps a two-input Concat to two K partials. The multi-slice
helper handles the four inputs of `/model.9/Concat`. For each consumer, the
first partial loads bias and does not mvout; later partials accumulate into the
same accumulator; the final partial performs requant, SiLU, and mvout.

The four dual-consumer mappings are:

```text
/model.12 -> /model.13/cv1, /model.13/cv2
/model.16 -> /model.17/cv1, /model.17/cv2
/model.19 -> /model.20/cv1, /model.20/cv2
/model.22 -> /model.23/cv1, /model.23/cv2
```

The validation/build driver is:

`scripts/yolov5nu_stage8c_single_consumer_splitk.py`

Its `dual` command generates the final all-consumer candidate.

## Validation evidence

Host validation directory:

`generators/gemmini/software/gemmini-ort/models/detection/stage8c_all_consumer_splitk/`

For five images and 17 consumer edges, validation checks:

1. slice requantization equals the materialized QDQ Concat;
2. split-K int32 accumulator plus bias equals the materialized Conv
   accumulator;
3. materialized and split-K Conv outputs are equal;
4. materialized and split-K SiLU LUT outputs are equal.

All hardware-path checks are exact. Additional checks pass:

```text
76/76 Conv QDQ reference checks
69 SiLU LUTs, 17664 exhaustive int8 mappings
7 Add groups, 458752 exhaustive input pairs
```

ORT debug graphs can change a floating-point Conv accumulation at a tie when
many intermediate outputs are exposed. The known `/model.17/cv3` observation
is limited to a few one-LSB Conv values in image142/image650 and does not
occur between the two integer hardware paths.

`fpga/xcvu13p/tests/yolov5nu_stage8/uart/stage8c-all-consumer-splitk-image025.txt`

approximately `6.187` to `8.137 FPS`.

## Remaining follow-up

Stage 8 Concat/Add dataflow work is complete as a software/FPGA candidate.
The five image-specific all-consumer ELF files have now passed FPGA double-run
admission against the hardware-aware integer reference. Their paths and SHA256
values are recorded in `docs/YOLOV5NU_STAGE8_ELF_MANIFEST.json`. The remaining
Stage 8 optimization and qualification sequence is:

1. `[冻结]` Stage 8F 双消费者输入 slice Scratchpad reuse 已在五张固定图片上
   各双跑一次，class/sigmoid/DFL/Top-10/NMS 全部与 hardware-aware reference
   一致。平均端到端为`6123155 cycles`，比8C baseline减少约`0.45%`。
2. `[放弃]` Stage 8G Add-accumulator 到后续 Conv 的`mvout_spad`链路。原因是单链路
   理论端到端收益约`0.1%~0.5%`，且一次`mvout_spad`无法同时保持Add scale和Concat
   scale的两阶段bit-exact舍入。8G不替代8F baseline，相关候选仅作为历史生成物保留。
3. `[完成候选验证]` Stage 8H split-K configuration/fence merge。五图 FPGA 全部
   bit-exact；`/model.9/cv2/conv/Conv`局部减少约`3.4K cycles/7.2%`，但端到端平均
   比8F高约`1.28K cycles/0.02%`，不替代8F baseline。详见
   `docs/YOLOV5NU_STAGE8H_SPLITK_CONFIG_FENCE.md`。
4. Stage 8F remains the final Stage 8 baseline; enter Stage 9 and tune ordinary
   Conv and split-K Conv tiles separately.

Stage 9 Gemmini Conv tile tuning remains separate from the current final
Stage 8 dataflow candidate.
