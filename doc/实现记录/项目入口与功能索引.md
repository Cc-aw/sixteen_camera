# 项目入口与功能索引

本仓库是供 SoC 合并的视频与 AI 外设底座。四阶段目录整理记录保留历史过程；当前目录、入口和配置以下文及根 README 为准。

## 输入清单与配置

`config/manifests/` 是手写 RTL、SoC、IP 和约束的正式清单位置。根 Makefile 默认选择 `dual16` 集成示例，另保留 `single4`：

| 配置 | 示例 | 固件 |
| --- | --- | --- |
| `dual16`（默认） | 双 Gemmini16 | `build/firmware/gemmini_dual16_video_yolov5nu.elf` |
| `single4` | 单 Gemmini4 | `build/firmware/gemmini_single4_video_yolov5nu.elf` |

```bash
make help
make check
make firmware SOC_VARIANT=single4
make bitstream SOC_VARIANT=single4
make elaborate SOC_VARIANT=single4
make test-cache SOC_VARIANT=single4
make test-tensor
make test-runtime
make test-software
make outputs
```

硬件构建使用 Vivado 默认综合与实现设置。固件在 `build/firmware/`，bitstream 和本次报告在 `build/bitstream/<配置>/<运行标识>/`。本机路径通过 `config/tools.local.mk` 覆盖，模板为 `config/tools.example.mk`。

## 合并新 SoC

`rtl/control/control_soc_subsystem.sv` 实例化计算侧 harness；`rtl/top_wrapper.sv` 连接板级视频、MMIO、DDR 和 FBus。先匹配端口、地址/ID 位宽、时钟/复位、缓存一致性与寄存器协议，再替换生成 RTL。

```bash
make check SOC_CONFIG=<generated/soc/下的完整配置目录名>
make bitstream SOC_CONFIG=<配置目录名>
```

`SOC_CONFIG` 优先于示例别名，只选择硬件。新 SoC 的软件需要独立适配 `sw/Makefile` 中的参数/ABI，以及 `sw/src/ai/backend/`。不得将示例 ELF 直接当作新 SoC 固件。

`setup_vivado.tcl` 更新共享 XPR 的源文件集合。构建和 elaboration 使用 `build/video_project.lock`；切换配置后应重新检查、构建并匹配硬件/固件。

## 功能定位

| 功能 | 实现入口 | 验证入口 |
| --- | --- | --- |
| 顶层与 SoC 适配 | `rtl/top_wrapper.sv`、`rtl/control/control_soc_subsystem.sv` | `make check`、`make elaborate` |
| 摄像头、HDMI、显示 | `rtl/video/`、`sw/src/video/` | `make test-video` |
| Tensor 打包与 DMA | `rtl/ai/preprocess/`、`rtl/ai/tensor/` | `make test-tensor` |
| DDR、FBus、CDC | `rtl/memory/`、`rtl/bus/` | `scripts/test/run_tensor_write_optimization_tests.sh`、`scripts/test/run_fbus_generated_path_test.py` |
| PPU 与 Head 发布 | `rtl/ai/postprocess/`、`sw/src/ai/postprocess/` | `make test-ppu`、`make test-cache` |
| 流式调度与计算后端 | `sw/src/ai/runtime/ai_batch_runtime_stream.c`、`sw/src/ai/backend/` | `make test-runtime`、`make test-software` |
| 参考 SoC 生成 | `soc_shell/`、`scripts/generate/` | 各生成脚本的检查入口 |

通用队列/PPU 的多 worker 能力与阵列尺寸无关，保留现有容量与测试。输入清单检查只验证文件和选择关系；不能替代功能仿真、整机时序或板测。

S02 Direct DDR、L2 Invalidate 和移除 FBus 的文档属于待实现方案。当前 Tensor 仍经 coherent FBus 写入。
