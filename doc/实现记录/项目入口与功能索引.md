## 构建配置

`config/manifests/` 是构建输入的唯一清单位置：

| 文件 | 用途 |
| --- | --- |
| `rtl_manifest.tcl` | 手写生产 RTL 白名单 |
| `soc_manifest.tcl` | 按 `SOC_VARIANT` 选择一份冻结 SoC RTL |
| `ip_manifest.tcl` | Xilinx IP 配置 |
| `xdc_manifest.tcl` | 约束及加载顺序 |

这些文件从 `build/` 迁出；`build/` 中的已有运行记录保留。
旧文档中的 `build/*_manifest.tcl` 路径应替换理解为 `config/manifests/*_manifest.tcl`。
本机工具路径可以写入被 Git 忽略的 `config/tools.local.mk`，格式参考
`config/tools.example.mk`。

## 使用入口

在项目根目录运行 `make help`。默认配置仍为 `triple64`，下一步 S02 实验可显式选择 `single4`：

```bash
make check SOC_VARIANT=single4
make firmware SOC_VARIANT=single4
make elaborate SOC_VARIANT=single4
make bitstream SOC_VARIANT=single4
make test-cache SOC_VARIANT=single4
make test-tensor
make test-runtime
make test-software
```

| 选择 | 硬件配置 | 固件输出 |
| --- | --- | --- |
| `triple64`（默认） | 三颗 Gemmini64，100 MHz 配置 | `build/firmware/gemmini_triple64_video_yolov5nu.elf` |
| `single4` | 单颗 Gemmini4×4 | `build/firmware/gemmini_single4_video_yolov5nu.elf` |
| `dual16` | 双颗 Gemmini16×16 | `build/firmware/gemmini_dual16_video_yolov5nu.elf` |

选择只对本次命令生效，不改写默认 manifest。`setup_vivado.tcl` 在实际构建时
会更新共享 XPR 的源文件集合，因此当前打开的 Vivado 工程可能保留最后使用的配置。
切换配置后，应重新执行对应的检查和构建，并下载相匹配的 bitstream / ELF。

三路64比特流继续走原 0918 流程；其他 SoC 使用
`scripts/build/build_default_video_bitstream.tcl`，明确恢复 Vivado 默认综合和实现参数，
清除共享 XPR 中上次专用流程遗留的 step 参数和 Tcl hooks。
已命名配置的输出复制到 `build/bitstream_<variant>/<时间戳_PID>/`。
生成 bitstream 不等于满足时序，需检查该目录的 `timing.rpt`。
第一阶段不自动下载、连接开发板或执行完整比特流构建。

## 更新与新增 SoC

更新已有 SoC 的生成 RTL，只需同步到原 `generated/soc/<名称>/gen-collateral/`，
然后重新构建；目录名称不变就不需要修改 manifest。
`make check` 只检查输入清单和文件存在性，不对比 RTL 内容或版本。
比特流入口自动执行一次输入检查；固件编译不再依赖硬件清单检查。

新增 SoC 可直接指定生成目录名，硬件构建不需要新增脚本或修改别名表：

```bash
make bitstream SOC_CONFIG=<generated/soc/下的完整目录名>
```

`SOC_CONFIG` 优先于 `SOC_VARIANT`。该方式要求生成 RTL 与现有板级 wrapper 接口兼容。
构建入口按实际选中的 SoC 判断流程：当前三路64配置使用 0918，其余使用 Vivado 默认流程。
新的 worker 数量、Gemmini DIM 或指令接口仍需相应的软件 ABI 适配；
`SOC_CONFIG` 只选择硬件，不自动推导固件参数。

常用配置可在 `config/tools.local.mk` 写入 `SOC_VARIANT := single4`，之后直接
运行 `make firmware`、`make bitstream`。显式命令行选择仍可覆盖本机默认值。

## 功能对应关系

以下路径均相对项目根目录。

| 功能 | RTL / 软件入口 | 测试与检查入口 |
| --- | --- | --- |
| 顶层、SoC、板级连接 | `rtl/top_wrapper.sv`、`rtl/control/control_soc_subsystem.sv` | `make check`、`make elaborate` |
| 摄像头、HDMI、显示 | `rtl/video/`、`sw/src/video/video_service.c` | `make test-video` |
| Tensor 打包和 DMA | `rtl/ai/preprocess/`、`rtl/ai/tensor/` | `make test-tensor` |
| DDR、FBus、CDC | `rtl/memory/`、`rtl/bus/` | `scripts/test/run_tensor_write_optimization_tests.sh`、`scripts/test/run_fbus_generated_path_test.py` |
| PPU、Head 发布和缓存控制 | `rtl/ai/postprocess/`、`sw/src/ai/postprocess/ai_ppu_publication.c`、`sw/src/ai/postprocess/ai_ppu_queue.c` | `make test-ppu`、`make test-cache` |
| 流式推理调度 | `sw/src/ai/runtime/ai_batch_runtime_stream.c`、`sw/src/ai/backend/ai_model_backend_yolov5nu.c` | `make test-runtime`（现有 host 测试覆盖 2/3 worker） |
| SoC 源码生成 | `soc_shell/npu100_video/`、`scripts/generate/generate_taihang_single4_rtl.sh` | 各生成脚本自身的检查入口 |

FBus 与缓存控制的生成 RTL 测试通过 `scripts/test/project_config.py` 调用 Tcl manifest，
与硬件选择保持一致。`test-cache` 目前测试 Flush64 的完成协议，尚未实现 Invalidate64 测试。
