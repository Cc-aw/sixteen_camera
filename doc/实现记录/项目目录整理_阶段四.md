# 项目目录整理：第四阶段

日期：2026-09-29。

## 新产物的默认位置

| 路径 | 内容 |
| --- | --- |
| `build/firmware/` | 三种视频固件 ELF、各自的编译目录，以及 standalone/smoke 固件 |
| `build/bitstream/<SoC>/<时间戳_PID>/` | 比特流、检查点、同一次运行的日志和时序报告 |
| `build/sim/ppu/` | PPU 持久化仿真缓存，缓存控制测试仍按生成 SoC 隔离 |
| `build/sim/loopconv/` | LoopConv/Gemmini 仿真生成文件和诊断日志 |
| `build/reports/elaborate/<SoC>/` | RTL elaboration 的工作目录 |
| `build/reports/ppu_phase2/<阶段>/` | PPU 独立综合快照、日志和报告 |
| `build/reports/program/` | 下载比特流和软件的日志 |
| `build/captures/` | 新导出的 Tensor 数据 |

目录在使用时创建，无需提交空目录。已有 `build/` 忽略规则覆盖新产物。
比特流报告与对应 bit/DCP 放在同一个运行目录，便于追溯。
已有使用 `/tmp` 且退出时清理的短时测试继续使用临时目录。
Vivado 项目管理的 `prj/*.runs`、`*.gen` 等仍由 Vivado 管理，统一入口将交付 bit 复制至上述运行目录。

## 入口变化

根目录的 `make check/firmware/bitstream/test-cache` 用法保持一致。
固件构建脚本、三个视频下载脚本和 `sw/run.sh` 已同步默认路径，例如：

```bash
make firmware SOC_VARIANT=single4
# ELF: build/firmware/gemmini_single4_video_yolov5nu.elf
bash scripts/program/download_single4_video.sh --check
make bitstream SOC_VARIANT=single4
# 新运行目录: build/bitstream/single4/<时间戳_PID>/
make outputs
```

`make outputs` 是只读盘点，显示目录大小和保留策略，不删除任何文件。
`ELF_FILE`、`--output`、`RESULTS_DIR`（triple64）、`PPU_TEST_CACHE`、`CAPTURE_DIR` 等已有显式覆盖继续有效。
直接 `make -C sw` 的默认输出也移到 `build/firmware/<SoC>/`。
双16正确性脚本明确传入 `SOC_VARIANT=dual16`，并使用同一构建目标的 ELF，修正其原先沿用默认 triple64 且读取另一旧路径的问题。

## 旧产物和清理边界

本次统一后续输出，不批量迁移或删除已有运行记录：

- `build/bitstream_0918_video/` 约 14GB，包含历史 bit、DCP 和恢复构建证据，保留原路径；旧 `RESUME_SYNTH_DCP` 仍可使用。
- `build/ppu_phase2/` 约 1.8GB，混合综合、仿真和 bit，不能整目录视作缓存。
- `build/sim_loopconv/` 约 1.4GB，包含故障诊断证据，保留。
- `reports/` 约 448MB、`captures/` 约 1.8MB，属于旧报告和板测输入，保留。
- `sw/build/` 约 351MB，保留旧固件和缓存；后续常用入口已不再向这里写入。
- `obj_dir/` 约 158MB、根 `.Xil/` 约 230MB 属于缓存候选，清理前需确认没有相关进程使用。
- `generated/soc/`、`generated/xilinx_ip/` 是构建输入；`artifacts/` 是冻结交付，均保留。
- `prj/` 混有 XPR、BD 源文件和 Vivado 产物，不能整目录清理。

以上大小为整理前的本机盘点值。实际大小以 `make outputs` 为准。
README 内容未修改；旧实现/验证记录保留当时的产物路径。
本次不归档 YOLOv2 源码、不修复其旧链接问题，也没有增加自动批量删除命令。
