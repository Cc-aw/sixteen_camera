# CSC-R1 C1a：G1 功能原型验证

**G1：PASS（下述功能模型契约内）；物理实现决策：INSUFFICIENT_EVIDENCE。**

两条物理 Input 半区描述符只省略完整同址 tile 的 Mvin，保留原配置命令、真实 RS 完成路径及关闭回退。没有增加数据 SRAM，没有启用 Weight 复用。

三路各一帧、每帧 166 个原生 stage：逐字节比较 11,441,748 次 SPAD 读取、1,578,600 个输出写回 beat，全部一致。原生命令、DMA row/credit、ROB、TL source 和真实 bank 接收/提交账本全部闭合。Accumulator 在原生 fence 边界共比较 6,029,312 字节。

四模式三路三帧、不同输入/换帧、双 slot/物理地址覆盖、原始配置恢复、SPAD 写入失效、隔离模式切换、真实晚到 denied/corrupt 和复位恢复通过。关闭 CSC 后 411,621 条 C0 事件连同周期完全一致。

实际少发 3,694,464 字节 Get，占完整 C0 流量 **4.1665%**。这是本有界实现的流量结果，不是 G0 无界机会或吞吐提升。保守排空会增加控制等待；原尺寸功能模型已显示这种开销，不能仅凭省 Get 推进 bitstream。

低延迟私有内存诊断中，第 0 路功能窗口从 7,214,307 增至 7,277,810 周期（增加 63,503，0.8802%）。此数只说明当前保守控制的开销；它不包含真实共享访存和 HOST/PPU 时间，不是系统吞吐测量。应先收窄排空依赖、保留关闭回退，再做 G2，当前不建议物理实现。

模型使用实际 RS/EX/FP16/存储/DMA RTL，外存由私有确定性物理内存服务替代，HOST padding 按原生操作执行；尚未接入生产 frontend 的失效接口，也没有共享 DDR/ASRAM 争用、CPU/RVV/PPU 周期或物理时序证据。G2 仍为 INSUFFICIENT_EVIDENCE，不报告系统 FPS，不执行综合、布局布线、bitstream 或上板。
