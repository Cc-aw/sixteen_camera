# NVDLA × Gemmini 访存优化筛选结果

对应[逐项筛选计划](../architecture/NVDLA_Gemmini_访存优化_逐项仿真筛选_Codex计划.md)。本轮按用户要求结束筛选，仅保留结果；测试源码、实验 RTL、生成模型、原始日志/trace 和中间证据已清理。尚未完成的矩阵已停止，不再作为运行中任务。

结论：继续使用现有 A1 + ASRAM 基线。E3 返回 FIFO 在所测范围内功能可行，但收益不成立；其余方向存在流量或结构机会，尚无足够证据支持进入生产硬件。CSC 的外部测试显示流量下降，周期改善很小。

## 各优化点结论

| 项目 | 可行性与本轮结果 | 处理建议 |
|---|---|---|
| E1 CSC 复用 | 外部 CSC-R1 报告限定 G1 功能通过；Get 字节减少 4.166522%，私有功能窗口仅减少 66 cycles，约 0.000915%。本轮独立导入尚未完成 | 有流量价值；不能据此认定整网加速 |
| E2 写合并 | 两帧观察到 217,492 对形状满足的候选写；完成、可见性、fault 语义尚未证明。该数量不是合法合并数 | 有潜力，暂不准入 |
| E3 返回 FIFO | depth 1/2 × 同拍 refill 开/关的四组参数均通过限定 G1；首个完整周期矩阵中 179/192 项变慢 | 当前实现不建议采用 |
| E4 WBUF | 16 种配置回放存在局部命中机会，但与现有 L2 重叠，尚无闭环收益 | 暂不建议增加硬件 |
| E5 跨组读合并 | 两包缓存观察到 90,856/1,287,996 次全命中 Get，潜在 payload 4,150,912 B；实际抑制、credit、生命周期和 fault 分发未证明 | 保留研究方向，暂不准入 |
| E6 预取 | 有 Load/EX 等待重叠，但更早发起所需的源数据、配置、ROB 与目标生命周期安全窗口未证明 | 暂无已证实收益 |
| E7 容量 / bank | 有效已加载字节峰值 343,042，小于 524,288 B；四种 XOR 映射引入新冲突，未测得周期收益 | 无扩容依据，暂不改映射 |
| E8 QoS | 源码确认共享交换结构，尚未测得真实共享 L2/DDR 的 Age、HOL、饥饿或公平性收益 | 证据不足，暂不改仲裁 |
| E9 融合 | 存在 HOST pad、pool、resize 等流量机会，消费者和可见性边界尚未闭合 | 作为独立融合项目 |

E2、E4～E9 的 G0 结论为 INCONCLUSIVE；流量上界、回放命中或重叠等待均不能当作实际节省周期。没有通过全系统 G2、组合验证或物理评审 GO。

## E3 已完成周期结果

[逐项周期结果 CSV](nvdla_memory_screening_cycles.csv) 保留八组矩阵共 **1,184/1,536 项**已完成 checkpoint 比较（77.08%）；[机器可读汇总](nvdla_memory_screening_results.json) 保留各组统计和历史元数据 SHA。

只有 periodic、depth2/refill0 的完整 192 项矩阵通过独立完成证据审计。其余七组为部分完成记录；清理时未重新逐份校验原始 trace 哈希，也没有因此授予新的 G1/G2 资格。

完整矩阵覆盖 1/3 active lanes × 私有 DDR 服务基础延迟 1/7/31 × 八个紧凑层（stage 0/2/4/5/8/10/59/132）× 四种 DMA 模式。实际执行 Gemmini、Frontend 和 ASRAM，输出字节、Get 集合、接受命令以及完成/credit 检查通过。该范围不包含完整网络及真实共享 L2/DDR/CPU/RVV/PPU 的系统时序。

| 1 | 1 | −1.5704%～+0.0793% | 3 |

完整矩阵中 **179 项变慢、9 项持平、4 项略快，48 项 mode2 全部变慢**。吞吐增益按 `baseline_cycles / candidate_cycles - 1` 计算；不把各层百分比相加或换算整网 FPS。

典型回退：单路延迟 1 的 stage0/mode2 为 3322→3375 cycles，stage8/mode1、mode2 均为 548→554。三路延迟 31 的 stage0/mode2 为 7043→7060，stage132/mode2、mode3 均为 141531→141543。

192 项 Reader D 背压累计均下降，但其中 179 项完成周期上升。stage0/mode0 单路延迟 1 的背压从 644 降到 168 lane-cycles，层周期却从 4841 增到 4858。mode2 的 96 条 lane 记录平均 Load 完成延迟全部增加，增量约 0.0690～1.3871 cycles。背压减少不能直接计作可回收壁钟周期，也不能排除调度相位的影响。

随机 Ready 三路延迟 1 的新增 32 项中，depth1/refill0 为 25 慢、0 平、7 快，6 项回退超过 1%；其他三组各为 22 慢、2 平、8 快，4 项回退超过 1%。随机服务相位会随执行进度改变，局部正收益不能外推成整网收益。

四组 FIFO 的限定功能验证均通过；声明的存储代理为 depth1 三路合计 810 bits、depth2 合计 1,614 bits，未测 PPA 或时序。关闭使用 depth0/C0 配置，未实现按层动态旁路。

## 其他量化观察

- E2：两帧 972,300 次 Put；217,492 对形状候选是在排除 62,108 对完成边界后得到。潜在减少请求/Ack 不等于已经证明合并合法，也不减少有效输出字节。
- E4：32～256 KiB、直接映射/两路、32/64 B 的 16 种 WBUF 配置中，256 KiB 直接映射 64 B 回放每帧少取 79,808/82,432 B；64 KiB 直接映射 32 B 仅少取 832/5,568 B。这是 L2 bank 串行回放结果，未证明真实 DDR 减流或性能改善。
- E5：候选缓存命中潜在 payload 中 bias 2,487,040 B、weight 576 B、activation 1,663,296 B；52,456 次命中跨 Load。未实施实际事务抑制。
- E6：观察 97,908 次提交 Load、60,773,600 B 写入；发起后的目标旧版本无读写冲突，不能证明提前发起安全。等待计数存在重叠，不能相加作为收益。
- E7：未初始化/未写入的 7,045,152 B 读取不计入有效占用峰值；四种可逆 XOR 映射新增 113,770～189,557 次已接受访问冲突，没有闭环改善证明。
- E8：实际 SBus 为六输入、四输出、两 L2 bank；source 命名空间的 544 个槽位不是实测 outstanding 容量或公平性保证。
- E9：两帧 12 次 HOST pad 共 460,800 B；stage73 每帧写 38,400 B 后有多个 HOST 消费者，Resize83/97 分别写 153,600/307,200 B。69 个 SiLU 和 13 个 Concat 已被消除，不能重复计算收益。

## CSC 外部结果的边界

CSC 由另一进程负责，本轮未清理其源码、测试归档或构建目录。外部已提交的[CSC 结果](../../hw/versions/csc_r1_streaming_asram_512kib_2bank/RESULTS.md)报告：三路各一帧、166 stage 的 Get 从 88,670,208 降到 84,975,744 B，节省 3,694,464 B（4.166522%），Weight/Bias 不变；lane0 功能窗口从 7,214,307 降到 7,214,241 cycles，其他两路同样减少 66 cycles。

这些结果使用私有确定性内存服务，未证明真实系统吞吐、整网 FPS 或板上收益。本轮只读复核了外部归档和当前源码身份；独立 G1 导入因新旧证据引用同一路径的两个历史生成器版本而未闭合。这是证据身份解析限制，不能据此断言数值错误，也不能宣称本轮独立验收完成。
