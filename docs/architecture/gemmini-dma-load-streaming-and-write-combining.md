# DmaLoadGroup 流水优化与跨命令 SPAD 写合并实施方案

日期：2026-10-17。状态：实现设计与实验计划。

优先实施 **DmaLoadGroup 按逻辑行就绪重放**：保留命令内的原始访存与写入语义，使后续数据返回、前部逻辑行恢复、缩放和 SPAD 写入同时推进。跨命令 SPAD 写合并先进行真实执行 trace 采集和离线收益分析，通过明确的投入门槛后才实现硬件。

本阶段聚焦流水、正确性和性能归因；全芯片时序由另一条工作线处理。基础协议沿用[短读合并与行组装方案](gemmini-dma-load-coalescing.md)，继续使用当前模型输入布局、L2 和双 Group 上下文，独立生成实验候选。

## 1 当前证据与实施顺序

### 1.1 最新微基准揭示的边界

同一硬件 `2a95a4ca64390235` 上，`C=12 B、N=32、P=2、scale=1、lane=0`。每模式 12 个正式样本，每样本连续提交 32 条 mvin 后等待排空，周期包含 CPU 提交和轮询，排除初始化、回读和 UART。

| 用例 | legacy 周期每命令 | 仅合并读 | 合并读与组装 | 联合模式相对 legacy |
| --- | ---: | ---: | ---: | --- |
| 连续 stride=12 | 80.529 | 76.844 | 60.323 | 加速 1.335 倍 |
| 非连续 stride=64 | 68.367 | 68.406 | 89.109 | 耗时增加 30.34% |

连续用例每命令 Get 为 `36 / 6 / 6`，实际 SPAD 写为 `72 / 64 / 33`；非连续用例为 `32 / 32 / 32` 和 `64 / 64 / 33`。两个用例均完成输出、保护字节和计数验证。原始记录见 [OPS32 日志](../../sw/board_tests/dma_spad_micro/logs/micro_ops32_01/micro.log)及[对比摘要](../../sw/board_tests/dma_spad_micro/logs/micro_ops32_01/comparison_ops1_ops32.json)。这些实验文件位于本地忽略目录。

单命令 `OPS=1` 的连续用例由 222.167 变为 229.167 周期，联合模式也没有降低单条延迟。当前证据支持优化流水重叠，但不能把非连续用例多出的全部周期归因于整命令屏障。`collect`、返回等待、重放、缩放、头部阻塞和上下文复用都需要分别观测。

首层联合模式并行加速 2.338 倍，整网已记录测量的并行加速约 1.163 倍；整网套件的记录完整性范围沿用[板测记录](../validation/gemmini-dma-load-coalescing.md)。流水优化应在保住这些收益的同时改善非连续和短命令，不承诺固定加速倍数。

### 1.2 分阶段决策

| 阶段 | 工作 | 出口 |
| --- | --- | --- |
| A1 | 消除整命令返回屏障，保持收齐输入描述符后发请求 | 提前重放得到 RTL 证明，原读写工作量和完整输出不变 |
| A2 | 根据 A1 计数决定是否让描述符收集与读请求也重叠 | 不增加不必要的 Get，不破坏命令接收契约 |
| B0 | 在 A1 稳定版本采集 SPAD 访问、命令与消费者 trace | 能重放每次观察，能解释所有不能合并的边界 |
| B1 | 扫描有限写缓冲容量和等待时间 | 得到合法合并率、延迟代价和投入判断 |
| B2 | 仅在 B1 达标后实现跨命令写合并 | 依赖保护、完成、排空与性能闭环均通过 |

新增的 `spad_assembled` mode 3 属于已有源码中的读合并消融功能；原板测硬件仍只有三模式。流水开关和跨命令合并开关使用独立 elaboration 参数，保留现有 2 位模式编码；生成上下文记录模式覆盖、流水版本及合并参数。

## 2 源码中的屏障与完成边界

当前 [DmaLoadGroup.scala](../../hw/soc/source/shell/npu100_video/src/main/scala/gemmini/DmaLoadGroup.scala) 使用两个 1 KiB 上下文和 `free → collect → fetch → emit → retire` 状态链。

1. 收齐 `cmd_rows` 个行描述符后才能进入 `fetch`。
2. `issued == total && received == total` 后才进入 `emit`。
3. 只有 `head` 能重放；收到整组完成信用后才释放上下文并推进 `head`。

因此两个上下文能重叠不同组的部分工作，但同一组的数据返回与逻辑行重放被第二条条件隔开。当前 32 个字节 bank 的 `SyncReadMem(64, UInt(8.W))` 已提供分离的读写接口，可以作为流式重放的数据存储基础。

必须保留实际的完成边界：[Scratchpad.scala](../../hw/soc/source/shell/npu100_video/src/main/scala/gemmini/Scratchpad.scala) 在最终写 token 被 `OrderedBankWrites` 接受时产生 load completion；它不是实际 SRAM 写入的同义词。队列中的地址继续参与 `readHazard`，非空状态参与 `bankWritesPending` 和 `busy`。实际写次数另在 `bio.write.fire` 计数。

`read_coalesced` 逐逻辑行归还有效字节，累计到 `N*C`；组装模式在尾部最终 token 被接受时归还一次 `N*C`。这两种记账方式保持不变，不能因物理返回变早而提前释放整条命令的依赖。

## 3 A1 按逻辑行就绪重放

### 3.1 分离进度与生命周期

保留两个上下文、整命令空间预留、原 Reader/source 分配、原读规划、共享缩放器和 RowAssembler。把互斥的 `fetch/emit` 改为同一个可同时读入和重放的 `active` 阶段；`retire` 只表示逻辑行已经全部调度，仍需等待输出和信用排空。

```mermaid
flowchart LR
    A[收齐行描述符] --> B[active 上下文]
    B --> C[Reader 发请求]
    C --> D[按 owner 和 offset 返回]
    D --> E[数据 RAM 与字节有效位]
    E --> F[head 下一逻辑行已就绪]
    F --> G[同步读与重放队列]
    G --> H[缩放与 RowAssembler]
    H --> I[有序 bank 写队列]
    I --> J[SPAD 写入]
    I --> K[原命令信用与上下文回收]
```

每组至少保留以下独立进度：

| 状态 | 含义 |
| --- | --- |
| `accepted_rows`、`collect_done` | 已接受的描述符；A1 在收齐后启动 |
| `issued_bytes` | 已交给 Reader 的逻辑有效字节 |
| `received_bytes` | 已接收且校验合法的唯一有效字节，仅作总量账本 |
| `valid_bytes` | 哪些逻辑字节已写入组缓冲 |
| `next_read_row` | 下一个尚未调度同步读的逻辑行 |
| `replay_fired_rows` | 已真正从重放队列交给下游的行数 |
| `credited_bytes` | 下游已归还的命令有效字节 |
| `physical_inflight` | 本组已接受但尚未消费最终返回片段的物理请求数 |

`received_bytes >= (row+1)*C` **不能作为就绪条件**：较后的事务可能先返回，收到的字节总量不证明前部行没有空洞。

### 3.2 字节有效位与乱序返回

每上下文配置 `32 words × 32 valid bits`，对应 1 KiB 数据。两组共 2,048 个有效位，即每 lane 256 B 元数据，三个 lane 共 768 B，不包含控制寄存器。首版用寄存器保存有效位，分字读取，避免一个整宽 1,024 位移位器。

有效位在分配上下文时清零，不清空数据 RAM。合法片段 `(group_id, offset, bytes, data)` 到达时，在同一时钟沿写数据并置对应有效位。片段至多覆盖两个逻辑 32 B 字；同周期对同字的更新必须合并成一次 next-state 赋值。

接受片段前检查 owner 仍有效、`offset + bytes <= N*C`，以及本次有效字节不与已接收字节重复。重复覆盖、越界或错误响应进入 sticky fault；不能靠重复累加 `received_bytes` 凑满命令。零有效字节片段不置位，但仍处理事务结束和错误信息。

对于行 `r`，逻辑起点始终为 `r*C`，与源地址 stride 无关：

```text
begin = r * C
word  = begin >> 5
shift = begin & 31
need  = ((1 << C) - 1) << shift       // 64 位中间值
have  = concat(valid[word+1], valid[word])
row_ready = (have & need) == need
```

越过缓冲上界的第二字按零处理，不进行数组越界访问。零填充命令在收齐描述符后逐行合成零，不读取未初始化的 RAM，也不经过浮点缩放去计算零。

只使用上一周期已经登记的有效位决定同步读，不做 D 返回到重放输出的组合旁路。一个片段可以使多行就绪，但重放仍最多每周期调度一行。

### 3.3 同步 RAM 与重放反压

保留已有非穿透重放队列，并在发出同步读时预留下一拍结果的位置：

```text
can_read = head_active && row_ready && !fault
           && replay_queue_has_space_for_registered_read
```

`next_read_row` 只在同步读被调度时推进；真正的下游接收另计 `replay_fired_rows`。数据、mask、cmd_id、group_id、first/last、scale、地址偏移等随同步读保存，不能使用已经推进后的描述符拼接上一拍返回的数据。队列反压时 payload 保持稳定。

只使能当前逻辑行覆盖的字节 bank，其他字节在恢复和旋转后显式置零。有效字节此前已经返回，并禁止重复写，因此可以断言：本次有效读与本拍写不命中同一 `{group, word, byte bank}`。这也避免了读取未选中字节与正在到达的新片段发生无意义的同址碰撞。`SyncReadMem` 的同沿同址读写结果没有定义，不能把底层 RAM 的特定行为作为正确性条件。[Chisel 内存语义](https://www.chisel-lang.org/docs/explanations/memories)

继续只重放 `head`，后一组可以提前请求和接收，但不能越过前组写入。A1 不同时引入跨组输出乱序，也不改变 RowAssembler 的 `group_first/group_last`、半区下溢、尾部 mask 和 `P-1` 个尾部步骤。

### 3.4 事务排空与完成

建议给 `DmaLoadFragment` 增加内部 `transaction_last` 标志，由 Reader 在实际最终 D beat 上生成，随返回队列一起传输。当前规划器将一个 Group 请求限制为一个 32/64 B 物理事务；请求被接受时增加本组 `physical_inflight`，消费带结束标志的片段时减少。同周期增减合并计算，不能覆盖更新。Reader 回归应明确检查一请求一事务；未来若允许拆分，须改为在实际事务分配处计数。

这条信息用于证明事务已经排空，不改变 TL source 分配、不复制 LoadController 的 cmd_id。不能只依赖有效字节数判断再无旧响应；也不能用整个 Reader 的全局 idle 代替本组排空，否则另一组的正常流量会重新引入组间屏障。

终止信用必须同时满足：收集结束、唯一有效字节齐全、物理在途数为零、全部逻辑行已交给下游、组装尾部已产生且被有序写队列接受、没有 fault。零命令豁免物理读取条件，其余记账一致。

普通 `read_coalesced` 行信用可提前返回；**仅将本组累计信用补足到 `N*C` 的那一笔**受终止条件约束。不能把“每行最后一个重复写”都当作“整组最后一个写”而重新阻塞前部重放。若终止条件尚未满足，应反压最后的写 token；不能消费 token 后再丢弃无反压的 `Valid` completion。

上下文释放还须保证该组不再被 held request、同步读结果或重放队列引用。A1 保留原有 `head` 随整组信用回收前进的规则；同周期释放与重新分配采用明确定义的优先级，首版允许隔一拍复用。

### 3.5 提前写入后的错误语义

消除返回屏障后，后部事务出错时，前部行可能已经写入 SPAD。现有存储没有回滚机制，因此定义为：**失败命令允许留下部分写入，但不发布该命令的成功完成，不允许依赖它的后续计算开始。** 已经完成的更早命令不被撤销。

Reader 与 Group 的 fault 都应进入统一的停止发布条件。错误当拍与终止 token 同时出现也不能产生成功完成；必要时在最终信用之前增加已保留容量的寄存确认阶段。审查 Scratchpad 的完成路径，不能只给 `can_read` 加 fault 门控，因为下游队列可能已经保存 token。

故障后继续接收、消费已发出的响应，不再分配新组；busy/fault 保持，受影响上下文不复用。此前普通行信用不等同于整组完成。恢复仍使用覆盖 Reader、Group、缩放、组装和相关队列的协调复位。

## 4 A2 再决定是否提前发读请求

A1 暂时保留收齐描述符的约 32 行接收阶段，用于单独证明消除返回屏障的收益。如果计数显示收集延迟仍限制吞吐，再让读请求追随已接受的行前缀。

首版不预读尚未握手的描述符所代表的数据。逻辑允许范围为 `accepted_rows*C`；非连续读按已接收行发出，连续读可等到前缀足够形成原 32/64 B 片段时再发出。命令末端或有限等待期限到达时允许发短片段，防止等待后续描述符形成死锁。

提前发读可能把一个原本能合并的请求切碎，必须同时比较 Get 和实际返回字节，不能只看首行延迟。若 `accepted_rows` 在请求反压期间增长，规划器的 `remaining` 会变化；此时必须锁存完整请求 payload，仅保持原来的 `heldSelection` 已经不够。

A2 的收益独立于 A1 记录。没有计数证据时不扩大上下文数量，也不改变 Reader 仲裁公平性或共享缩放器的吞吐配置。

## 5 流水观测与验证

### 5.1 计数口径

保留 external ID 8～34 的编号和已有含义。`LOAD_FETCH_WAIT_CYCLES` 在新状态机中应继续表示“至少一组仍等待读取完成”的周期，不能直接累计整个 `active` 生命周期。它会与有效重放重叠，不是可直接回收的 stall 预算。

先在仿真中记录下列指标，确认有用后再分配新增硬件计数器。新增 ID 从 35 起扩展，同时更新计数能力、源码、固件快照和日志 schema，不能静默覆盖旧编号。

| 指标 | 定义和用途 |
| --- | --- |
| `head_row_missing_cycles` | head 有待重放行，但该行字节未齐 |
| `head_row_ready_blocked_cycles` | 行已齐而同步读结果位置或下游空间不足 |
| `replay_before_all_return_rows` | 本组返回未齐时已交给下游的逻辑行数 |
| `fetch_replay_overlap_cycles` | 某组仍有读取未完成且同组发生重放握手 |
| `other_group_ready_head_blocked_cycles` | 后组具备数据但不能越过 head |
| `head_retire_wait_cycles` | 数据已交付，仍等待尾部或命令信用 |
| `context_full_cycles` | 有新命令等待但没有可分配的上下文 |
| 组时间戳 | 首描述符、收集结束、首请求、首片段、首重放、末片段、尾写入队、最后物理写 |

同时保留 Get、D 字节、组装 token、真实 SRAM 写、尾部步骤、bank 读阻塞和写反压。时间戳以单组为单位，区分“返回有进展”和“仍在等待返回”。多个条件可重叠，不将计数相加当作总执行时间。

### 5.2 必须增加的定向回归

| 场景 | 必须证明 |
| --- | --- |
| 延迟最后一个物理事务 | C=3/N=32/P=6 和 C=12/N=32/P=2 在末事务返回前出现前部重放；真实 SPAD 集成中前部写也能发生 |
| 先返回后部行 | 后部数据再多，也不能越过缺失的前部字节；无缺口的前部可以继续 |
| 字节跨界 | 覆盖所有 0～63 源偏移、C=1～31、N=1/2/31/32，以及逻辑行跨缓冲字边界 |
| 同周期读写 | 覆盖同组相邻行和不同组；有效字节无同址碰撞，未选中字节不会泄漏 poison 或 X |
| 输出持续反压 | 同步读结果有预留位置，数据与 tag 不错配，释放后不重放重复行 |
| 两组与 ID 复用 | 两组返回交错，仍按命令顺序重放；旧组最后事务消费前不能回收身份 |
| 早期行信用 | 仅合并读可以逐行完成，组装只在尾部完成；每命令累计信用恰好 N*C |
| 晚到错误 | 若干 SPAD 写已发生后注入 denied/corrupt/错误 owner；无成功完成、无依赖计算、fault/busy 保持 |
| 错误与最后 token 同拍 | 覆盖 Reader fault、Group fault 和返回队列延迟，错误优先于成功完成 |
| 零命令与半区边界 | 无 TL 读取、正确零语义、裁剪后的 mask/尾部与原路径一致 |
| 路径切换和末条命令 | legacy/Group 切换、DRAIN、HOST、DONE、无后续命令都能正确处理 pending |

独立参考继续使用原逐行、逐重复 masked write 模型，比较完整目标区域、未选中字节及保护行。错误用例不能只检查 final RAM，正常用例也不能只检查网络最终 PPU 输出。

### 5.3 性能与身份验收

A1 与“整组返回后重放”的对照候选保持模式、模型布局、C/N/P、源偏移、L2、频率和软件调度一致；Get、D 字节和实际 SPAD 写的工作量应逐项相同。若不相同，先解释行为差异，不把工作量变化算成流水收益。

微基准至少复测原 continuous/strided 的 OPS=1 和 OPS=32，再扫描 OPS=2/4/8/16/64、C=3/12/16、P=1/2/6 的合法组合、短 N 与长 N，以及三个 lane。分别报告单命令延迟、批次周期和摊销吞吐。原测试连续使用同一源和目标，只代表该局部工作负载，应另加不同目标区、不同源工作集和并发访问的对照。

结构验收要求延迟末事务时仍能推进前部写，保证不是换名后的整组缓冲。性能验收要求目标非连续批量用例相对旧 Group 有稳定改善，连续访问和完整首层/整网没有超出测量噪声的回退；是否已追平 legacy 单独报告。建议用多轮均值、中位数和范围判定，1% 作为初始回退复查线，不作为预设收益。

## 6 跨命令合并的机会与上界

跨命令合并以 **已经完成命令内行组装后的写入流** 为基线。不能再次把 legacy 的 P 次重复写减少量计入新增收益。

最清楚的候选是连续目标区的命令边界。若相邻 K 条命令各有 N 个输入行、重复数 P、相同 C/P，目标起址每次推进 N 行，同一半区内没有裁剪，每条命令独立输出 `N+P-1` 个目标行。前一条的 P-1 个尾部行与后一条的前部行重叠，其不同字节段可在没有观察者时合并。

```text
独立组装写数 = K * (N + P - 1)
理想合并写数 = K * N + P - 1
节省写数     = (K - 1) * (P - 1)
长序列极限   = (P - 1) / (N + P - 1)
```

这些是满足上述条件的理想上界，不是当前 trace 的测量值。`N=32/P=6` 的极限约 13.51%，`N=32/P=2` 约 3.03%；短 N 可能更值得关注。源地址是否相邻不决定这些 SPAD 写能否合并，必须检查实际目标地址、mask 和观察顺序。

保留 P-1 行的尾部可能需要多项缓冲。例如 P=6 时，前一条的五个尾部目标行先到，后一条从最早的重叠行开始；只比较 FIFO 最后一项通常匹配不到。应使用实际 `sp_bank()/sp_row()` 映射统计每 bank 所需项数，不能假定地址按 bank 轮转。

## 7 B0 真实 trace 的补充采集

### 7.1 现有记录能证明什么

已检查 `build/experiments/dma_load/512kib_2bank_runtime_20261016/final_layers/`。三份 `rows_lane*.csv` 各有 31,161 条记录、每条 12 个字段，覆盖八个缩小空间尺寸的真实层、三种模式。联合模式每 lane 包含 638 条命令、10,387 个逻辑行。

当前字段为：

```text
case, mode, first, last, index, rows, cmd_id,
address, cols, pixels, stride, zeros
```

其中 `address` 是源 vaddr。记录没有目标 laddr、实际写 mask、周期、EX/mvout 读取、插入写和屏障，cmd_id 还会复用。它可以闭合原始行请求与 Get，却不能算出可靠的跨命令合法合并率；当前没有据此投入写合并硬件的证据。

### 7.2 采集层级和字段

优先对实际 Gemmini RTL 执行真实计划进行仿真探测，增加仿真专用日志，不先增加板上 trace 硬件。首批覆盖首层、stage 2/4/5/8/10/59/132；在缩小用例检查探针后，采集完整尺寸的层及其相邻执行阶段。全网结论需要全网或覆盖充分、带权重依据的完整执行记录，不能直接外推缩小用例。

以 A1 稳定候选为主要基线，同时保留旧流水对照。改流水会改变命令间距和可合并窗口，旧 trace 的命中率不能自动继承。

公共字段记录 `schema, build_id, lane, cycle, event_seq, frame, stage, epoch`。`cmd_seq` 是每 lane 单调的逻辑命令编号，区别于循环复用的 `cmd_id`、`group_id` 和 TL source。epoch 由明确的排空/阶段边界建立，不在每条 mvin 自动切换。

| 事件 | 必要字段与用途 |
| --- | --- |
| `LOAD_ACCEPT` | cmd_seq、cmd_id、ROB 关联、src、完整 laddr、C/N/P/stride、scale、zeros；记录命令接收顺序 |
| `DMA_WRITE_CANDIDATE` | 组装后、bank 仲裁前的 valid/ready、cmd_seq、目标 bank/row、mask、处理后的 data、last；分析合并输入与反压 |
| `BANK_WRITE_ACCEPT` | 有序队列入口的真实 fire、EX/DMA/zero 来源、地址、data、mask、acc/覆盖类型；还原实际接受顺序 |
| `BANK_WRITE_COMMIT` | 实际 SRAM 写 fire、地址、data、mask、来源；闭合真实物理写数 |
| `READ_INTENT` | EX 和 DMA mvout 在依赖门控前的读请求、地址、稳定请求编号；识别已经等待观察旧值的消费者 |
| `READ_ACCEPT`、`READ_DATA` | 读握手、关联编号、返回 data；验证每次可观察结果 |
| `LOAD_CREDIT`、`CMD_COMPLETE` | 原信用字节、cmd_id/cmd_seq、ROB；检查完成及身份复用 |
| `BOUNDARY` | DRAIN、HOST、DONE、模式/格式切换、fault/reset；结束合并区间或建立新 epoch |

不能只记录读握手：若读已经在等待 pending 写排空，合并器不能利用这段等待继续吸收后来的写，让该读看见更晚版本。所有 EX/零写及旁路 DMA 写都须记录，即使首版不允许合并它们。相同周期的事件顺序由实际仲裁和握手定义，不让离线分析器自行挑选有利顺序。

每个 trace 区间从已知空闲和已知 SPAD 初值开始；否则保存初始 RAM、队列和在途请求快照。截断、丢事件、未知 owner 或中途开始但无快照的记录不能用于合法性统计。输出 payload 可压缩存储；不能只用校验和替代逐字节参考需要的数据。

## 8 B1 合法性模型与投入门槛

### 8.1 首版允许的合并

仅允许同 lane、同物理 SPAD bank/row、同 epoch、相同存储语义的普通 DMA 覆盖写。数据已经完成缩放/饱和，按字节 mask 组合：

```text
combined_mask = old_mask | new_mask
combined_data[byte] = new_mask[byte] ? new_data[byte] : old_data[byte]
```

重复字节保留较新的写值。即使 mask 不重叠，也必须证明两次写之间不存在应观察中间值的读；“同地址”或“mask 互补”都不是充分条件。相同 scale 也不是必要条件，因为此处已是转换后的数据，但 ACC 累加、EX 写和独立零写首版作为边界处理。

有限窗口只在连续的、没有观察者的普通 DMA 写片段内部查找相同目标行；不得跨过较老的冲突写或读。首版以每 bank 的读意图、EX 写、零写、旁路写类型变化为保守排空边界；先统计该策略是否还有收益，再决定是否值得细化到只阻止冲突地址。

读取意图到来时冻结窗口，先提交较老的 pending 写，并阻止较新的写越过该读取，直到读取被接受。只设置 `readHazard` 让读取无限等待而继续吸收新写，并不能保持中间值的观察语义。

### 8.2 离线分析的三层输出

1. **形态上界**：统计相同目标行、相邻命令尾首重叠、mask 分布和距离。此层不称为合法合并率。
2. **合法有限窗口**：逐事件重放，扫描每 bank 1/2/4/8 项和最大保留 0/4/8/16/32 周期；READ_INTENT、边界、容量满或期限到达触发排空。保留实际输入顺序，不用无限缓存估算可实现收益。
3. **周期候选**：加入 bank 接受能力、依赖阻塞、背压和消费者顺序，估算写口压力变化；固定输入时间戳的回放只给条件性估算。实际生产者会因反压改变，最终周期收益必须在闭环 RTL 和板测中确认。

参考模型同时运行原写序列和候选合并序列，逐次比较 `READ_DATA`、完成/屏障可见状态及最终 SPAD。检查对所有旧字节的保留，而非只比较最后一次覆盖后的 RAM。

每组结果至少输出：

| 指标 | 分母或含义 |
| --- | --- |
| `saved_writes` | 原物理 DMA 写数减候选实际写数；每个合并集合只计 k-1 次 |
| `saved_writes_pct` | 分母为当前组装基线全部 SPAD DMA 写，含零写；另列命中层和 eligible 子集比例 |
| `cross_cmd_saved_writes` | 只计 cmd_seq 不同带来的增量，排除命令内收益 |
| `merge_distance` | 相隔周期、写事件数、命令数和所需缓冲项数分布 |
| `flush_reason` | 读意图、EX/zero、边界、容量、年龄、格式切换各自造成的损失 |
| `extra_latency` | 每条命令信用、每次读、最终排空新增延迟及最大值 |
| `bank_pressure` | 实际受阻的写与依赖读；说明减少的写是否落在限制执行的阶段 |
| `correctness` | 所有观察一致、账本闭合、无事件缺失，否则整项无效 |

推荐产物为 `trace_manifest.json`、压缩事件文件、`combining_report.json` 和一份逐层摘要；manifest 固定候选、工作负载、初值、trace 哈希与探针版本。

### 8.3 决定是否实现硬件

以下是本项目建议采用的初始决策门槛，属于工程目标，不是当前已经达到的结果：

- 在不超过每 bank 8 项、最多保留 32 周期的窗口内，有明确的跨命令合法合并，全部读/完成观察一致。
- 全网加权物理 DMA 写数下降至少约 5%；或者某个已确认限制整网的阶段获得明显收益，周期模型支持至少约 2% 的端到端改善。不能仅用 eligible 子集的高命中率达标。
- 排空无需等待未来命令，读等待和短命令回退可控；任何超过 1% 的候选回退都需解释并给出旁路条件。
- 若只有大窗口、长延迟或忽略读取边界才有收益，暂不实现跨命令硬件，继续优化 A1/A2。

初始门槛允许根据完整 trace 调整，但应在查看最终性能对比前固定验收口径。通过门槛仅意味着值得做原型，不等于可以替换生产路径。

## 9 B2 达标后的硬件落点

### 9.1 在有序 bank 写入口建立可观察的缓冲

首版在每个 SPAD bank 的 EX/DMA/zero 仲裁之后、现有 `OrderedBankWrites` 之前增加小容量写合并缓冲，或将等价逻辑封装在该队列入口。保持现有 SRAM 接口和 ACC 路径。这样能看到该 bank 的真实接受顺序，不在 RowAssembler 内跨命令保留窗口和完成 tag。

每项保存 `valid、row、256-bit data、32-bit mask、epoch、oldest_age` 及必要来源信息。仿真另保存贡献者 cmd_seq，验证跨命令归因。普通 DMA 写可搜索窗口内相同行，并按较新 mask 更新；不同目标行只在同一无观察者片段内缓冲。EX、零写等边界到来时先排空较老内容，再允许边界操作通过。

容量和最长保留时间由 B1 结果选择，默认关闭。先比较“只合并已经同时在队列中的写”和“主动等待少量周期”两种策略；若需要主动等待，等待成本纳入结果，不能只报告少写了多少次。

某项一旦作为下游 `valid` 提出，便冻结它的数据和 mask，直到握手成功；即使下游反压，也不能继续将新写并入已提出的项。可继续接收并合并其他未提出的项，或者保守反压。

### 9.2 保持现有信用语义并扩展依赖保护

load 的末 token 被新缓冲**可靠接受并保存所有有效字节**时，仍可沿原通路归还本命令信用。不能在仅命中一个地址但未保存 payload 时发信用。所有写一旦被接受，最终提交责任转移给该缓冲。

这样不需要在一笔合并物理写后扇出多个 cmd_id completion，也不需要把已完成并可能复用的 cmd_id 留作控制身份。两条命令的完成各自对应原 token 接受；合并后 SRAM 物理写可以更少，二者不能混账。

为保持这个完成契约，必须同时完成以下接入：

- `readHazard` 覆盖合并缓冲和原有队列，包括同拍接受的新写；读意图触发第 8 节的冻结和顺序控制。
- `bankWritesPending`、Gemmini busy、DRAIN/HOST/DONE、模式和路径切换覆盖新缓冲；不能只看旧队列是否为空。
- 同 bank EX/DMA/zero 的冲突顺序不变。跨 bank 的依赖仍由原调度器及各 bank 保护共同保证。
- `c21` 继续计原组装 token 接受数，`c22` 继续计真实 SRAM DMA 写数；二者之差不能全部归为跨命令收益，另用贡献者账本验证。
- 完成 arbiter 继续每周期只发布允许的一笔原逻辑信用，不增加未经仲裁的 Valid 源。

若选择等实际 SRAM 写后才归还信用，则必须增加多命令提交账本、完成队列，并解开 Group head 与信用的耦合；这会显著扩大改动范围，首版不采用。

### 9.3 有界排空与死锁避免

每项年龄从最老贡献写进入时开始计算，合并命中不重置年龄。年龄到期、容量不足、读意图、外部写边界、模式切换或显式排空都触发提交。fault 时停止正常合并并服从整体错误恢复语义，不宣称失败命令成功。

**绝不能等下一条命令到来才提交上一条。** 下一条可能受上一条计算或完成依赖阻塞；Group 上下文和 load tracker 也可能都已占满。即使软件永久停止提交新命令，只要下游公平接受，最后一项也必须有限排空。期限触发提交并不意味着下游无限反压时还能保证固定完成周期。

验证需专门构造：A 的尾写等待合并，B 等 A 的计算，计算又等 A 的 SPAD 数据；年龄或读意图必须打断该等待环。另覆盖 mask 一直不满、同地址写持续到来、无后续命令、所有组槽已占用以及 mode switch 等待排空。
